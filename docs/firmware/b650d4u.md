# ASRock Rack B650D4U / B650D4U_2L2T BMC firmware: stack assessment

Status: preliminary. This was derived only from the static firmware images, by reading config files,
shell scripts, the web UI JS and init scripts, listing files, and running `strings`/`file` on binaries.
No binary was disassembled or decompiled. The Redfish Lua resource tree is covered in
`docs/redfish/`. This document describes only its architecture.

On the BMC, `/conf` is a writable JFFS2 partition. On first boot it is seeded from
`/etc/defconfig` (`R9/etc/init.d/mountall.sh`, `check_conf()`, lines ~296-312). Many `/etc` files are
symlinks into `/conf` (for example `R9/etc/nsswitch.conf -> /conf/nsswitch.conf` and `R9/etc/timeouts -> /conf/timeouts`).
For that reason the factory defaults quoted below come from `R9/etc/defconfig/*`.

**Important framing for the diff (section 7):** 7.02.00 and 9.05.00 are not two releases of one
product. They are builds for two different board SKUs, built on the same day from two git repos:
- `R7/info/git_info.log`: repo `b650d4u`, commit `c3e32243...`. `R7/info/B650D4U.PRJ`: "Fri, 17 Oct 2025 15:20:52 +0800", `FW_DESC="B650D4U"`, `PRODUCT_ID=0x2019`.

## 1. Flash layout, U-Boot/FIT, device tree

### 1.1 Image container
- Each image is 67,109,128 bytes: a 64 MiB SPI NOR (0x4000000) followed by a 0x108-byte trailer (264 B). The trailer is 256 bytes of signature data, then the magic `ef be ad de` (0xDEADBEEF LE), then `ff fe ff 03`. This matches `CONFIG_SPX_FEATURE_SIGNED_HASHED_IMAGE_SUPPORT` and `ASRR_SIGN_SUPPORT` (`R9/etc/core_features`, `R9/info/B650D4U_2L2T.PRJ`). The signature covers the image. I did not verify it.
- Flash geometry comes from `R9/etc/core_macros`: `GLOBAL_FLASH_SIZE=0x4000000`, `ERASE_BLOCK_SIZE=0x10000`, `FLASH_BANKS=0x1`, `UBOOT_MONITOR_SIZE=0x100000`, `UBOOT_ENV_START=0xf0000`, `UBOOT_ENV_SIZE=0x10000`, `MEMORY_START=0x80000000`, `MEMORY_SIZE=0x1f000000`, `NUMBER_OF_SECTIONS_IN_IMAGE=9`, `BIOS_COMPONENT_SIZE=0x2000000` (32 MiB host BIOS on a separate SPI, `pnor`).
- Partitioning uses AMI FMH ("Firmware Module Header", `$MODULE$` signature, FMH v1.8). The kernel DTB declares the BMC flash partitions node as `compatible = "ami,spx-fmh"` (`AG/dtb905_kernel.txt`, `spi@1e620000/flash@0/partitions`). The kernel discovers partitions by scanning FMH headers, so the DTB holds no fixed offsets.

- The section order comes from `R9/info/B650D4U_2L2T.PRJ` line ~1537: `GLOBAL,BOOT,CONF,BKUPCONF,ROOT,OSIMAGE,WWW,TESTAPPS,BOOTLOGO,AST2600EVB`. The PRJ also sets `FMHEnable=1`, `FMH_MAJOR=1`, `FMH_MINOR=8`, `Dupfstab=1` and `ProductId=1`.
- A `$MODULE$` hit at 0x8FF1D is a false positive (text inside U-Boot), and so is the zero entry at 0xCFFF8.
- Gaps between 0x3110000 and 0x3FF0000 (about 14.9 MiB) are unused or erased.
- Mounts come from `R9/etc/fstab`: `/dev/mtdblock1 /conf jffs2 nodev,noexec,nosuid` and `/dev/mtdblock4 /usr/local/www squashfs nodev,noexec,nosuid`. Root is `/dev/root`. `mountall.sh` also handles `/bkupconf` and `/extlog` and runs a fail-safe re-mkfs of conf from `/etc/defconfig` (`R9/etc/init.d/mountall.sh` lines 160-260).
- The 9.05 and 7.02 layouts are identical up to `root`. 9.05's root partition is 0x20000 smaller, so every later section moves down by 0x20000 (this is the 0x2680040 vs 0x26A0040 kernel offset).

### 1.3 U-Boot
- The version string is `U-Boot 2019.04 (Oct 17 2025 - 07:45:46 +0000)` (`strings` on `IMG9` [0:1MiB]). PRJ packages: `Bootloader_20XX_Pristine-13.0.1`, `Bootloader_20XX_amiext-13.132`, `Bootloader_20XX_platform_ast2600evb-13.1`, `asrruboot-1.0` (`R9/info/B650D4U_2L2T.PRJ` lines 9-21).
- Built-in default environment: `bootcmd=bootfmh`, `bootdelay=0`, `baudrate=115200`, `bootargs=console=ttyS4,115200n8 root=/dev/ram rw`. The env region 0xF0000-0xFFFFF is erased (all 0xFF) in the shipped image, so the built-in defaults apply.
- Strings show the boot path: `Boot using FMH Modules`, `Booting from MODULE_PIMAGE`, `Booting from Primary side`, `goldenside=1`, `imagebooted=%d`. Recovery strings: `Firmware Recovery is started...`, `TFTP Recovery Image Booting started...`, `CopyRecoveryImage ... ext4_read_file from SD`, `Both MMC and TFTP Recovery boot is failed`, `1. socflash Recovery`, `ASRR: SOCFLASH is enabled` (`CONFIG_SPX_FEATURE_ASRR_ENABLE_AST2600_SOCFLASH`). MFG mode: `init=/usr/local/bin/defshell MFG_MODE` (`CONFIG_SPX_FEATURE_MFG_MODE_SUPPORT=YES`).
- Aspeed secure-boot/OTP strings are present (`Secure Boot Mode: Mode_2`, `Mode_GCM`, OTP tool strings). These are the stock Aspeed U-Boot commands. The strings alone do not show whether secure boot is strapped on.
- Config options: `CONFIG_SPX_FEATURE_BMC_FIRMWARE_AUTO_RECOVERY`, `BMC_FIRMWARE_REBOOT_RETRY_COUNT=0x2`, `UBOOT_MEMTEST_SUPPORT`, `ASRR_FAN_INIT_IN_UBOOT` (`R9/etc/core_features`, `R9/etc/core_macros`, PRJ).

### 1.4 FIT image (osimage @ 0x2680040), parsed with `AG/fdt.py`
- `description = "U-Boot fitImage for LTS13 SPX/5.4.85-ami/ast2600"`. The description string is stale: the real kernel is 5.4.210, see section 2. `timestamp = 0x68f1f418` = 2025-10-17 07:45:28 UTC.
- `kernel@1`: type kernel, arch arm, os linux, compression none, 4,364,088 bytes, `load = entry = 0x80001000`, `hash@1 algo sha256`.
- `fdt@ast2600evb_a1.dtb`: 51,970 bytes, sha256-hashed.
- `configurations/default = conf@ast2600evb_a1.dtb`. The configuration carries only a hash (`hash@1 algo sha256`), with no `signature` node. FIT signature verification is therefore not enforced through FIT.

### 1.5 Device-tree model strings
- Kernel DTB (inside FIT, at 0x2AA996C): `model = "AST2600 EVB"`, `compatible = "aspeed,ast2600"`, `chosen/bootargs = "console=ttyS4,115200n8"`, `memory@80000000 reg = <0x80000000 0x80000000>`. Reserved memory: `region@b8000000` (64 MiB, no-map), `framebuffer` (16 MiB CMA, video capture), `ssp_memory` (2 MiB), `linux,cma` (64 MiB) (`AG/dtb905_kernel.txt`).
- U-Boot DTB (at 0xBE76C): `model = "AST2600 EVB"`, `compatible = "aspeed,ast2600-evb", "aspeed,ast2600"`, `stdout-path = /ahb/apb/serial@1e784000` (UART5 = ttyS4) (`AG/dtb905_uboot.txt`).
- Neither DTB contains an ASRock board string. The board identity lives only in FMH `FW_DESC` and the PRJ. Platform variant selection is done at runtime by per-SKU IPMI libraries under `R9/usr/local/lib/ipmi/ast2600evb_*` and `R9/etc/defconfig/BMC1/ast2600evb_*` (variants in 9.05: `1U1G`, `1U2E`, `1U4L`, `1U4LWR`, `BCM`, `ami`).
- SPI: FMC `spi@1e620000` has `flash@0 label="bmc"` (50 MHz, quad read) and partitions `ami,spx-fmh`. `spi@1e630000` has `flash@0 label="pnor"` (host BIOS). Ethernet: `ftgmac@1e660000` uses `phy-mode = rgmii-rxid`, and `ftgmac@1e670000` uses `use-ncsi` (U-Boot DTB). `CONFIG_SPX_FEATURE_NCSI_DEFAULT_INTERFACE=eth1` (`R9/etc/core_macros`). The default bond is `bond0 eth0,eth1 1 100` (`R9/etc/defconfig/bond.conf`).

### 2.1 init and runlevels
- `R9/etc/inittab`: default runlevel 3 (`id:3:initdefault:`) and sysinit `/etc/init.d/rcS`. Runlevels 7 and 8 are "Ractrends SP 4.0 Upgrade mode via Web or IPMI". Runlevel 9 is the warm-reset path (rc9.d). Runlevel 4 is the pre-flash stop set. The serial console is `getty -L console 115200 vt100` (console redirected to ttyS4 via `/conf/console_tty`).

**rc4.d (pre-flash):** this set stops most daemons (`K20procmanager ... K99forcekill`), then runs `S51stopgc, S52initcomplete`. ### 3.2 lighttpd: complete configuration files

Startup comes from `R9/etc/init.d/lighttpd.sh`: if `/conf/lighttpd.conf` is missing, the script copies it from `/etc/defconfig/lighttpd.conf` (and also to `/bkupconf/`). It then runs `/usr/local/sbin/lighttpd -f /conf/lighttpd.conf -m /usr/local/lib`. It exits early if `/var/tmp/licstat/lighttpd_nolicense` exists. Restarts happen from the `if-up.d/90-up-webserver` hook on every interface-up (`R9/etc/network/if-up.d/90-up-webserver`), and from `/usr/local/bin/lighttpd_delayed_restart.sh N` (called by spx_restservice). The `include` paths are relative to `/conf` (the file lives in `/conf`), and every included file is seeded from `/etc/defconfig`.

The identical copies `R9/usr/local/redfish/redfish_lighttpd.conf` and `.../redfish_lighttpd_bios.conf` have the same md5 as the defconfig ones (`22f1e212...` and `d57dddb4...`). `R9/usr/local/redfish/lighttpd.sh` is an older copy of the init script.

#### mod_singleport
- The module is `R9/usr/local/lib/mod_singleport.so` (PRJ `mod_singleport-13.19`, `libsingleportapp-13.9`). Its config is `R9/etc/defconfig/singleport.conf`: `[singleport] enabled=1`.

#### mod_evasive limits
- Global: `evasive.max-conns-per-ip = 30` (lighttpd.conf).
- `^/redfish`: `evasive.max-conns-per-ip = 10` (redfish_lighttpd.conf). The SSE URL also matches `^/redfish`, so long-lived SSE streams count against the 10.
- The module supports `evasive.silent` and `evasive.location` (strings `R9/usr/local/lib/mod_evasive.so`). Neither is set, so lighttpd 1.4.45 answers excess connections with **HTTP 403** and logs "turned away. Too many connections."
- The limit counts **concurrent connections per source IP**. It is not a request rate.

#### Other lighttpd behaviour that matters to a proxy
- `server.max-read-idle = 120` and `server.max-keep-alive-idle = 120` seconds.
- `server.stream-request-body = 2` and `server.stream-response-body = 1` (set globally inside redfish_lighttpd.conf). The request body streams to the backend without buffering, and the response streams with buffering.
- `server.errorfile-prefix = /usr/local/redfish/redfish_error_`: when the Redfish backend is down, lighttpd returns 503 with body `<html><body>redfish out of service</body></html>` (`R9/usr/local/redfish/redfish_error_503.html`). The body is **HTML, not a Redfish JSON error**.
- `Content-Encoding: gzip` is added for every URL that is not `/api`, `/ext`, `/redfish`, `/wsman`, `/fonts`, `.png` or `.jar`. The www squashfs files are stored pre-gzipped (`W9` was decompressed from them).
- For the SSE URL lighttpd sets `Content-Encoding: " "` (a single space), which is malformed. A strict client or proxy may reject it, so strip it.
- `url.access-deny` blocks `.xml`, `.jnlp` and `.dat` downloads outside `/api/` and `/redfish`, unless the Host header is `169.254.0.17` (the host-interface/in-band address).
- `debug.log-request-header` and `log-response-header` are enabled, so headers, including Authorization, may reach the error log.

### 4.1 Architecture (summary only)

- **Process:** a single LuaJIT 2.0.5 process runs `cd /usr/local/redfish; luajit server.lua` (Turbo-Lua HTTP server). The PID file is `/var/run/redfish-server.pid` and the server name is "AMI MegaRAC Redfish Service" (strings `R9/usr/local/redfish/config.lua`). Started by `R9/etc/init.d/redfish-server` at rcS S29, it also starts `redfish_pamauthd` and the sync-agent `init-agent.lua`, and registers with procmanager through `procmonitor-redfish.lua`. All `.lua` files in `/usr/local/redfish` and `/usr/local/sync-agent` are **LuaJIT bytecode** (header `1b 4c 4a 01`), not source.
- **Listeners:** `SERVICE_HOST`:9080 for the REST API and `SSE_SERVICE_PORT` 9090 for Server-Sent Events (`/redfish/v1/EventService/SSE`), both behind lighttpd. ### 4.2 How Redfish is enabled or disabled
- **Build-time:** `CONFIG_SPX_FEATURE_REDFISH_ENABLED=REDFISH` and `CONFIG_SPX_FEATURE_REDFISH_ENABLED=YES` (`R9/etc/core_features`, PRJ). `CONFIG_SPX_FEATURE_DISABLE_DRE=YES` and `RTP_1_2_1` are also set (PRJ).
- **Runtime:** neither ncml.conf nor the web UI has a Redfish on/off service entry. Redfish is reachable whenever (a) `redfish-server` is running and (b) lighttpd has `include "redfish_lighttpd.conf"`. To disable it you would edit `/conf/lighttpd.conf` or stop the init script. The default image has no switch for this.
- **Redis service flags:** `Redfish:EventService:ServiceEnabled`, `Redfish:TaskService:ServiceEnabled`, `Redfish:SessionService:ServiceEnabled`, `Redfish:AccountService:ServiceEnabled`, `Redfish:CertificateService:ServiceEnabled` and `Redfish:UpdateService:ServiceEnabled` are all `true` at init (db_init files). The event/task init scripts set these flags on start and stop (`R9/etc/init.d/event-service`, `task-service`). `Redfish:ServiceRunningStatus` is set to `true` by `server.lua` once Redis is connected (strings).
- **Flash mode:** the legacy API `/api/maintenance/redfish` (handler `putRedfishFlashMode`, in `R9/usr/local/bin/spx_restservice`) and `/api/maintenance/firmware/redfish` toggle Redfish into firmware-update mode.
- **Web enable timeout:** `libasrrspx_restservice` exposes `/api/asrr/getWebEnableTimeout` and `/api/asrr/setWebEnableTimeout` (strings). The name suggests an ASRR timer that re-enables web access. Its meaning is not confirmed.
- The `/redfish` proxy works only while the backend is up. If it is down, lighttpd returns 503 HTML (3.2).

### 4.4 Authentication methods
- **HTTP Basic:** handled inside `server.lua` and `redfish-handler.lua` (bytecode). Credentials are checked through `redfish_pamauthd`, a daemon reached over FIFOs `/var/pipe/RedfishPAMReqQ` and `/var/pipe/RedfishPAMResQ` (strings `R9/usr/local/bin/redfish_pamauthd`, linked against `libuserauth`, `libpamhelper`, `libldapauth`, `libradiusconf`, `libpam`). It uses the PAM service `HTTP`: `/etc/pam.d/HTTP -> /conf/pam_wounix`, so authentication goes through IPMI users, then LDAP, AD and RADIUS (section 6). `pam_ffi.lua` contains LuaJIT FFI PAM structs, so Lua can also call PAM directly. `config.lua` lists `USE_SPX_PAM`.
- **Redfish sessions:** `POST /redfish/v1/SessionService/Sessions` returns `X-Auth-Token`. `db_init/sessionservice.rcmd` sets `Redfish:SessionService:SessionTimeout 30`. The unit is not stated. Redfish defines seconds with a minimum of 30, so 30 s is plausible, but AMI UIs often use minutes. **Verify on hardware.** `config.lua` also has the constants `MAX_SESSIONS`, `SESSION_TIMEOUT`, `SESSION_TIMEOUT_POLL_INTERVAL`, `SESSION_TIME_LOWER_LIMIT`, `SESSION_TIME_UPPER_LIMIT`, `GC_INTERVAL` and `SESSION_PATH=/tmp/`. Their numeric values are inside bytecode and were not extracted.
- **mTLS:** lighttpd `ssl.verifyclient.activate=enable`, `enforce=disable`, `username=SSL_CLIENT_S_DN_CN`, `exportcert=enable`, `ssl.ca-file=/conf/ca.pem` (redfish_lighttpd.conf). The TLS handshake **requests** a client certificate but does not require one. When a client presents a cert that chains to `/conf/ca.pem`, lighttpd sets `REMOTE_USER` to the subject CN and exports the cert. Whether the Redfish backend accepts this as authentication is decided in Lua: `config.lua` has `ACCOUNTS_CERTIFICATE_DIR_PATH=/conf/redfish_cert/accounts` and `MAX_ACCOUNTS_CERTIFICATE_COUNT`, and `zzzaccountservice.rcmd` creates `Accounts:1:Certificates`. That points to per-account certificate mapping. **Note for the proxy:** lighttpd uses `mod_proxy` to reach port 9080 and passes the CN/cert only as environment variables. mod_proxy in 1.4.45 does not forward them as headers, so cert-based auth over `/redfish` probably does not work. Test this on hardware.
- **Default trust anchor:** `/conf/ca.pem` comes from `R9/etc/defconfig/ca.pem`, a self-signed AMI CA (`CN=www.ami.com`, `O=American Megatrends Incorporated`, valid 2018-04-23 to 2037-06-22). See 8.4 for the DHCP option-248 overwrite.
- **Account policy** (`R9/usr/local/redfish/db_init/zzzaccountservice.rcmd`): `AuthFailureLoggingThreshold 3`, `MinPasswordLength 8`, `MaxPasswordLength 20`, `MaxUserNameLength 16`, `AccountLockoutThreshold 5`, `AccountLockoutDuration 30`, `AccountLockoutCounterResetAfter 30`, `LocalAccountAuth "LocalFirst"`. `config.lua` lists the supported hash algorithms `MD5`, `SHA512` and `PBKDF2` (PRJ "PBKDF2 Password Hashing Support for Redfish").
- **Seeded account:** `Accounts:1` is `UserName "Administrator"`, `RoleId Administrator`, `PasswordChangeRequired true`, `AccountTypes Redfish`, with a static salt, PBKDF2 hash, SHA-512 hash and AES-encrypted password. **The AES key and IV that encrypt Redfish account passwords (`Redfish:AccountService:Accounts:AESKey/AESIV`) are hard-coded in this file and are the same on every unit.** `config.lua` refers to `/conf/AESKey` and `/conf/AESIV`, which may override them at runtime.
- **Roles:** Administrator (Login, ConfigureManager, ConfigureUsers, ConfigureSelf, ConfigureComponents), Operator (Login, ConfigureSelf, ConfigureComponents), ReadOnly (Login, ConfigureSelf), HostInterfaceAdministrator (all five plus OEM ConfigureHostInterface). The privilege registry is `R9/usr/local/redfish/privilege_registry/Redfish_1.3.0_PrivilegeRegistry.json` (`config.lua` `PRIVILEGE_REGISTRY_JSON_FILE`).

  passwd: files rsvdusers ipmi ldap ad radius redfish

### 5.2 Session protocol (from `strings` and the web UI `W9/source.min.js`)
- **Login:** `POST /api/session` with form fields `username` and `password`. The JSON response includes `ok`, `privilege`, `user_id`, `server_addr`, `passwordStatus` and `CSRFToken`. The server sets the cookie **`QSESSIONID`**, and the UI stores the token in cookie `garc`. Every later request must send the header **`X-CSRFTOKEN: <token>`**: the binary reads `HTTP_X_CSRFTOKEN`, and the UI does `$.ajaxSetup({headers:{"X-CSRFTOKEN":...}})`.
- **Logout:** `DELETE /api/session`.
- Error strings: "Could not create token for this session. Max session limit might have reached", "Insufficient Privilege", and status lines `400 Bad Request`, `401 Unauthorized`, `411 Length Required`, `413 Request Entity Too Large`.
- Tokens are tracked in `/var/ActiveWebTokens` and `/var/ActiveWebTokens1`. Sessions are registered with the AMI session manager (`libracsessioninfo`, `racsession_id`), and `/var/session_terminate` handles termination.
- Downloads use `X-Sendfile2` (`allow-x-send-file`).
- Default-password enforcement: "Password should be changed for default user and should have a minimum of 8 characters." (`/api/updatenew_password`, `/api/reset-pass`).
- `/api/settings/web_server_instances` rewrites `"max-procs"` in `/conf/lighttpd.conf` through `/tmp/lighttpd.conf` and restarts lighttpd with `/usr/local/bin/lighttpd_delayed_restart.sh 2` (strings). **This endpoint can raise the FastCGI concurrency above 1.**
- Web session timeout: `CONFIG_SPX_FEATURE_WEB_SESSION_TIMEOUT=0x708` (1800 s) (`R9/etc/core_macros`; PRJ `WEB_^SPX_REST^_SESSION_TIMEOUT=1800`), also ncml `[web] session_timeout=1800`, with configurable bounds 300-1800.

## 8. Proxy-relevant quirks

### 8.1 Rate and connection limits
- `mod_evasive` allows **10 concurrent connections per source IP for `/redfish*`** (including SSE) and 30 overall. A proxy usually presents one source IP, so it must pool and cap at about 8 or fewer concurrent upstream connections per BMC for Redfish. Leave headroom for SSE and keep-alive sockets. Excess connections get **HTTP 403** from lighttpd, not 429.
- `/api` FastCGI runs `max-procs 1`, so legacy API calls are serialised in a single process. Long calls (firmware upload, `X-Sendfile` downloads) block all other `/api` calls. `web_server_instances` can raise this.
- Redfish runs a single LuaJIT event loop with Redis as the store (maxmemory 20 MiB, `noeviction`). Large `$expand` queries are bounded only by Lua constants (`RESPONSE_SIZE_LIMIT`, `MAX_REQUESTBODY_LENGTH`, `DeepOperations_MaxLevels`, and `EXPAND_PARAMETERS` such as `LEVELS`/`MAX_LEVELS`; strings in `config.lua`, values in bytecode). Supported OData query parameters: `$select`, `$expand`, `$filter`, `$top`, `$skip`, `$count`, `$orderby`, `only`, `excerpt`, `format`, `inlinecount` (`SUPPORTED_ODATA_QUERY_PARAMETERS`).
- Idle timeouts are 120 s (lighttpd read and keep-alive). For SSE the proxy should send its own keep-alives or tolerate the BMC's: `Redfish:EventService:SSE:KeepAlive`, "Dummy string to keep the SSE clients Alive" (strings `event-service/ServerSentEvent.lua`). `websocket.timeout=0` applies to KVM/SOL.
- At most 36 IPMI sessions (all channels) and 15 users.

### 8.2 TLS
- **lighttpd :443:** the base list `"TLSv1.2 !SHA384 !SHA256 !RSA !SHA !aNULL !eNULL !EXPORT !DES !SSLv2 !3DES !RC4 !MD5 !PSK !DHE"` is extended by `+= " AES256:HIGH"`. In OpenSSL, `!` exclusions are permanent, so the effective TLS 1.2 set is ECDHE + AEAD only. `openssl ciphers -v` with local OpenSSL 3.5, which approximates on-device 1.1.1n, gives these suites for the default **RSA-2048** cert: `ECDHE-RSA-AES256-GCM-SHA384`, `ECDHE-RSA-CHACHA20-POLY1305`, `ECDHE-ARIA256-GCM-SHA384`, `ECDHE-RSA-AES128-GCM-SHA256`, `ECDHE-ARIA128-GCM-SHA256`. There is no static RSA, no DHE and no CBC. `ssl.dh-file=/conf/certs/dhparam.pem` is unused because of `!DHE`. SSLv2/3 are disabled. lighttpd 1.4.45 on OpenSSL 1.1.1 should also negotiate **TLS 1.3** by default, since the config sets no max protocol. Verify this with a live scan. A Go client with default settings is compatible.
- **stunnel (VNC):** `ciphers=AES256-SHA256:!RC4:HIGH:!MD5:!aNULL:!EDH:!AESGCM`, `sslVersion=TLSv1.2` (`R9/etc/defconfig/stunnel.conf`).
- **Redfish host-interface listener:** LuaJIT/Turbo SSL with `/conf/server.pem`.
- **Outbound event delivery** (event-service): the strings `sslv23`, `verify`, `none` show that **subscriber TLS certificates are not verified** (`R9/usr/local/redfish/event-service/event-service.lua`). Default retry policy is `DeliveryRetryAttempts 3` and `DeliveryRetryIntervalSeconds 60` (`db_init/eventservice.rcmd`).

### 8.4 Trust and security observations
- **DHCP option 248 can replace the mTLS CA.** `R9/etc/network/udhcpc.d/process-redfish-option.script` takes option 248 as a URL. If `Redfish:Configuration:CertificateAuthorityUrl` is empty, the script runs `wget`, downloads the URL and overwrites `/conf/ca.pem` (lighttpd's `ssl.ca-file`). A rogue DHCP server on the BMC LAN can therefore install a trusted client-CA. On a management VLAN with controlled DHCP this risk is acceptable. Elsewhere, set the Redis key or block option 248.
- Host interface with `AuthNone` → Administrator (4.3). Anything running on the host OS can administer the BMC over USB-NIC unless the host interface is disabled.
- There is a static AES key and IV for Redfish password storage, a static default TLS key, and a static `sysadmin` hash (sections 4.4, 6.1, 8.3).
- `PermitRootLogin yes` (uid 0 `sysadmin`) over SSH (3.6).
- Request and response headers are logged (`debug.log-request-header="enable"`).
- `server.tag = "lighttpd"`. lighttpd adds HSTS/CSP to non-API paths only.

### 8.5 Event services
- **Redfish EventService** (`db_init/eventservice.rcmd`):
  - Enabled.
  - `EventTypesForSubscription`: StatusChange, ResourceUpdated, ResourceAdded, ResourceRemoved, Alert.
  - `EventFormatTypes`: Event, MetricReport.
  - `RegistryPrefixes`: Base, SyncAgent, Security, EventLog, IPMI, HttpStatus, Task.
  - `ResourceTypes`: Chassis, Managers, Systems, AccountService, EventService, TelemetryService, TaskService.
  - `SubordinateResourcesSupported false`.
  - SMTP primary and secondary are disabled (port 25, secure port 465).
  - `MAX_EVENTS_DESTINATION` caps subscriptions ("Maximum Event Destination Limit reached").
- **SSE:** `GET /redfish/v1/EventService/SSE` reaches lighttpd, which proxies to 127.0.0.1:9090 and returns `text/event-stream`. The `$filter` grammar supports `EventFormatType eq ...` and the `LastEventId` field. The SSE client count is in `Redfish:EventService:SSE:NumClients` (bounded by `MAX_SSE_CLIENT_CONNECTION`), and keep-alive interval comes from `SSE_KEEP_ALIVE_RECCURENCE_INTERVAL` (strings `ServerSentEvent.lua`, `config.lua`). Mind the malformed `Content-Encoding: " "` header (3.2) and the 10-connection evasive cap.
- **TaskService:** enabled, `CompletedTaskOverWritePolicy Oldest`, `LifeCycleEventOnTaskStateChange true` (`db_init/taskservice.rcmd`). Task monitors are stored under `Redfish:TaskService:TaskMonitors`.
- **TelemetryService:** seeded by `db_init/telemetryservice.rcmd` and run by the sync-agent `telemetry.lua`.
- **Legacy alerting:** IPMI PEF/LAN destinations (`/api/settings/pef/*`), SNMP traps (`libautosnmp`) and SMTP (`/api/settings/smtp`).
- Redis keyspace notifications (`KEA`) drive internal change propagation. Writes made over IPMI or the legacy `/api` show up in Redfish asynchronously, through the sync-agent and IPMI2Redfish.
