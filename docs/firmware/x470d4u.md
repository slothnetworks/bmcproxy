# ASRock Rack X470D4U BMC firmware 3.02.00: stack analysis

Status: preliminary assessment for the native Go proxy. Static analysis only: I read config files, shell scripts, plain-text Lua, JS and certificates, ran `strings`/`file`/`readelf -d` on binaries, and parsed FMH/uImage headers. Nothing was disassembled, decompiled or executed. LuaJIT bytecode (`1b 4c 4a` magic) was inspected with `strings` only.

Source image: `/opt/sparked/asrockrack-api/bmc-firmware/X470D4U_3.02.00.ima` (33,554,432 bytes = 32 MiB SPI flash).

Path conventions used below:

- `root/...` = extracted CramFS rootfs, `/tmp/claude-1000/-opt-sparked-asrockrack-api/152d9ce5-3665-4f40-8521-6ab266196a9e/scratchpad/fw/x470/root/...` (on the BMC this is `/`)
- `www/...` = decompressed web partition, `.../scratchpad/fw/x470/www_plain/...` (on the BMC this is `/usr/local/www`)
- `api.txt` = `.../scratchpad/fw/x470-api.txt` (endpoint list scraped from the web UI)
- `/conf/...` = runtime JFFS2 config partition. At first boot it is populated from `root/etc/defconfig/`. In the extracted tree, several `root/etc/*` files are symlinks into `/conf`.

## 0. TL;DR for the proxy

| Topic | Finding |
|---|---|
| **Redfish** | **Present, compiled in, and enabled by default.** It is started unconditionally at boot and served at `https://<bmc>/redfish/v1` through a lighttpd `mod_proxy` to `127.0.0.1:9080` (AMI "MegaRAC Redfish Service", LuaJIT/Turbo). Neither `ncml.conf`/`/api/settings/services` nor the web UI has an on/off switch. Details and evidence in section 4. |
| Legacy REST | `/api/*` is FastCGI to `/usr/local/bin/spx_restservice` on the unix socket `/tmp/spx_restservice.socket`. Auth is `POST /api/session` (form: `username`, `password`, `certlogin=0`). It returns a `QSESSIONID` cookie and a `CSRFToken`, which must be echoed back as the `X-CSRFTOKEN` header. |
| Web server | lighttpd 1.4.35 with OpenSSL 1.0.1t, so TLS 1.2 at most and no TLS 1.3. The default cert is the self-signed AMI cert `CN=www.ami.com` (RSA-2048, valid to 2037). Its private key ships in firmware. The server *requests* (but does not enforce) a client cert on :443. |
| IPMI | `IPMIMain`, RMCP/RMCP+ on UDP 623 (the standard port; the configured value lives in NVRAM, not in a text file). 36 total sessions, 10 users, session timeout 60 s. |
| KVM | HTML5 (H5Viewer, `viewer.html`/`viewer.min.js`) over WebSocket `wss://<bmc>/kvm`, which lighttpd `mod_websocket` maps to `127.0.0.1:7578`. Virtual CD uses `wss://<bmc>/cd-server` mapped to `127.0.0.1:5120`. Java JViewer (`/Java/jviewer.jnlp`) also ships. |
| Sessions | Web: `max_sessions=148`/`active_sessions=128` and a 1800 s timeout (`ncml.conf [web]`). KVM: 1800 s. Redfish `SessionTimeout 30`, account lockout after 5 failures for 30. |
| Rate limiting | `evasive.max-conns-per-ip = 30` is set, but `mod_evasive` is **not** loaded, so in practice there is no rate limiting. A single FastCGI process (`max-procs 1`) handles `/api`, so requests are serialized and the proxy should limit its own concurrency. |

### 1.2 AMI FMH ("$MODULE$") table

I parsed the module headers directly from the image. Each header starts with `$MODULE$`, FMH v1.8, 0x40 bytes. Fields are: allocated size at +0x0C, location at +0x10, name at +0x18, module version/type/location/size at +0x20.

| FMH header @ | Block size | Module name | Module ver | Type | Payload @ | Payload size | binwalk hit | Role / mount |
|---|---|---|---|---|---|---|---|---|
| 0x0003FF00 (at end of block) | 0x50000 | `boot` | 2.4 | 0x01 | 0x00000000 | 0x39728 | (U-Boot) | U-Boot 2013.07 (built Aug 26 2021 10:03:26). Region 0x0–0x3FFFF. |
| n/a | (in boot block) | U-Boot env | n/a | n/a | 0x00040000 | 0x10000 | n/a | **Blank in the image (all 0xFF).** U-Boot falls back to its compiled-in defaults (section 1.3). |
| 0x00050000 | 0x180000 | `conf` | 2.4 | 0x11 | 0x00060000 | 0x170000 | **JFFS2 @ 0x60000** | `/dev/mtdblock1` mounted at `/conf` (JFFS2), per `root/etc/fstab` |
| 0x001D0000 | 0x180000 | `conf` (2nd copy) | 2.4 | 0x11 | 0x001E0000 | 0x170000 | JFFS2 magic `85 19 03 20` present (binwalk listed only one conf) | Backup config, `/bkupconf`. `root/etc/init.d/mountall.sh` (lines 120–177) mounts conf plus bkupconf, re-creates either from the other or from `/etc/defconfig` if corrupt, and keeps them in sync (`rsyncconfd`). |
| 0x00350000 | 0x1370000 | `root` | 2.4 | 0x12 | 0x00360000 | 0x1355000 | **CramFS @ 0x360000** | Root filesystem, read-only. The kernel cmdline in U-Boot is `root=/dev/mtdblock%d ro ip=none mem=%dM`, and `/dev/root` is `/` in `root/etc/fstab`. |
| 0x016C0000 | 0x2C0000 | `osimage` | 2.4 | 0x06 | 0x016C0040 | 0x2B0120 | **uImage @ 0x16C0040** | Linux kernel uImage: name `Linux-3.14.17-ami`, OS=Linux, arch=ARM, type=kernel, uncompressed, load/entry 0x80008000, size 0x2B00E0, built 2021-08-26 02:02:56 UTC |
| 0x01980000 | 0x80000 | `dre` | 0.12 | 0x11 | 0x01990000 | 0x70000 | **JFFS2 @ 0x1990000** | `/dev/mtdblock3` mounted at `/dre` (JFFS2). This is the AMI "Dynamic Redfish Extension" store used by `/usr/local/redfish/oem/dre` and `/usr/local/sync-agent/oem/dre`. |
| 0x01A00000 | 0x4D0000 | `www` | 2.4 | 0x11 | 0x01A10000 | 0x4B7000 | **CramFS @ 0x1A10000** | `/dev/mtdblock4` mounted at `/usr/local/www` (cramfs). The files are stored gzip-compressed without a `.gz` extension, which is why lighttpd adds `Content-Encoding: gzip`. |
| 0x01FF0000 | 0x10000 | `ast2500e` | 3.2 | 0x02 | 0x01FF0040 | 0x88 | n/a | Firmware version record (below) |

Firmware version record at 0x1FF0040 (plain text):

```
FW_VERSION=3.02.00
FW_DATE=Aug 26 2021
FW_BUILDTIME=10:12:20 CST
FW_DESC=X470D4U
FW_PRODUCTID=1
FW_RELEASEID=RR9
FW_CODEBASEVERSION=3.X
```

Another `$MODULE$` string appears at 0x2FE2F. It is not a header: it is inside U-Boot's string table, next to the cmdline template `root=/dev/ram0 ro ip=none ramdisk_blocksize=4096 mem=%dM`.

MTD numbering, inferred from `root/etc/fstab`: mtd1=conf, mtd3=dre, mtd4=www, and root comes from the U-Boot `root=/dev/mtdblock%d` cmdline (mtd2 by ordering). bkupconf is located dynamically by `mountall.sh`.

### 1.3 U-Boot defaults

The env sector is blank, so U-Boot uses its compiled-in env (from `strings` of 0x0–0x3FFFF):

```
bootcmd=bootfmh          (AMI: scan FMH table, boot osimage + root)
bootdelay=0              (no interactive window by default)
baudrate=0x1c200         (115200)
ethaddr=00:00:00:00:00:00 (MAC comes from EEPROM: I2C ch 7, addr 0x57, offsets 0x0/0x8 per core_macros)
prompt: AST2500EVB>
```

### 2.1 Init system

This is SysV `init` (BusyBox/sysvinit style), configured by `root/etc/inittab`:

- `id:3:initdefault:`, so the default runlevel is 3.
- `si::sysinit:/etc/init.d/rcS` runs `rcS.d` first.
- `l0`..`l9` run `/etc/init.d/rc N`. Runlevel meanings: **0** halt (`rc0.d -> rc6.d`), **1** single, **3** normal, **6** reboot, **7/8** "Ractrends SP 4.0 Upgrade mode via Web or IPMI" (firmware flash), **9** warm reset (`K1warm-reset-begin` … `S99warm-reset-complete`).
- `co:2345789:respawn:/sbin/getty -L console 115200 vt100`

Note: in the extracted tree, the `rc*.d` entries are zero-length placeholder files rather than symlinks, but their names (S/K + priority) give the order. Each init script also documents its links in `#Runlevel :` comments.

### 3.4 TLS details (for the Go client)

- Protocols: OpenSSL 1.0.1t, with SSLv2 and SSLv3 disabled. lighttpd 1.4.35 has no knob to disable TLS 1.0/1.1, so it offers **TLS 1.0, 1.1 and 1.2**, and no TLS 1.3. Go's default client minimum (TLS 1.2) works.
- ECDHE curve: `secp384r1` only (`ssl.ec-curve`). Go supports P-384. Note that OpenSSL 1.0.1 with a single `ssl.ec-curve` can fail ECDHE negotiation if the client does not offer P-384. Go offers it by default, but do not restrict `CurvePreferences` to X25519/P-256 only.
- Cipher list: the long list above, plus `" AES256:HIGH"` appended by `redfish_lighttpd.conf`. Go-compatible suites in it include ECDHE-RSA-AES128/256-GCM.
- Client certificates: on :443 the server sends a CertificateRequest (`ssl.verifyclient.activate = "enable"`, CA `/conf/ca.pem`) but does not require one (`enforce = "disable"`). The Go client should leave `Certificates` empty, or present one if cert-login (`certlogin=1`, `/api/asrr/session`) is ever used. The CN is exported as the username (`SSL_CLIENT_S_DN_CN`).
- Default server certificate `/conf/server.pem` (from `root/etc/defconfig/server.pem`, which contains **both cert and private key**): subject `C=US, O=American Megatrends Incorporated, OU=Service Processors, L=Norcross, ST=Georgia, CN=www.ami.com, emailAddress=support@ami.com`. It is self-signed, RSA-2048, sha256WithRSA, valid 2018-04-23 to 2037-06-22, SHA-256 fingerprint `ED:4D:A7:C3:E9:E0:43:49:ED:37:6D:AA:81:70:86:FA:26:7D:C1:1F:75:46:6F:9B:85:00:65:34:B2:92:BD:18`. **The key is public (it is in the firmware)**, so pin per-BMC certs only after they have been regenerated (`/api/operations/ssl/certificate/generate`, `/api/settings/ssl/certificate`).
- `/conf/ca.pem` (`root/etc/defconfig/ca.pem`, same content as `ca-default.pem`): AMI CA, RSA-2432, valid 2018 to 2037. It is used for client-cert verification and can be replaced over DHCP option 248 (section 4.6).
- Response headers: `Server: lighttpd/1.4.35` (`server.tag = "lighttpd"`), and `X-Frame-Options`, `Cache-Control: no-store...`, `X-Content-Type-Options` and `X-XSS-Protection` on non-API paths. Static responses carry `Content-Encoding: gzip` **unconditionally**, regardless of the client's `Accept-Encoding`. A proxy that re-serves static UI must pass the bytes and header through untouched or decompress them.

## 4. Redfish on the X470D4U

### 4.1 Verdict

**Redfish is present, enabled by default, and reachable on the LAN at `https://<bmc>/redfish/v1`. The firmware has no switch to turn it off.** The belief that "the X470D4U does not expose Redfish" is **not supported** by firmware 3.02.00. The REST `/api` path is still useful for ASRock-specific features (fan control, BIOS flash, MCA logs and similar), but Redfish should be treated as available, and the proxy can probe it.

Caveat: this conclusion comes from static analysis. Verify on a live unit with `curl -k https://<bmc>/redfish/v1` (expect the AMI ServiceRoot JSON; it is normally unauthenticated) and `curl -k -u admin:<pw> https://<bmc>/redfish/v1/Systems/Self`. Two things could explain a unit that does *not* answer:

1. If `/conf` was preserved across an upgrade from an older pre-Redfish firmware, `lighttpd.sh` never overwrites an existing `/conf/lighttpd.conf`, and an older file would lack `include "redfish_lighttpd.conf"`.
2. The web UI has no Redfish page, so nothing in the UI advertises it.

### 4.7 How Redfish is toggled

- **No runtime on/off control was found.** There is no `[redfish]` section in `ncml.conf`, and the Services API/UI (`/api/settings/services`) is driven by `ncml.conf`. No `/api/settings/*redfish*` route exists in `spx_restservice`; its only "redfish" strings are `redfish` and `/conf/redfish/bios/*`, which are BIOS-settings files. The web UI has no Redfish page.
- The init scripts check no flag. Only `redisrsync` checks the build-time `CONFIG_SPX_FEATURE_REDFISH_ENABLED`.
- Inside Redis, `Redfish:<Service>:ServiceEnabled` exists per sub-service, and the handler has `error_service_disabled` / `ServiceDisabled`. This is per-service Redfish state (for example SessionService), changeable through Redfish PATCH, not a global kill switch.
- Host interface: `Redfish:Managers:Self:HostInterfaces:Self:InterfaceEnabled`, `KernelAuthEnabled` and `FirmwareAuthEnabled` are settable through Redfish (Managers/Self/HostInterfaces) and through IPMI OEM (`libipmiamioemrestiface`).
- DHCP option 248: `root/etc/network/udhcpc.d/process-redfish-option.script` (identical to `root/usr/local/sync-agent/extensions/ipmi/process-redfish-option.script`). If DHCP supplies option 248 (a URL), the script stores it in `Redfish:Configuration:DHCPCertificateAuthorityUrl`. If `Redfish:Configuration:CertificateAuthorityUrl` is empty, it `wget --no-check-certificate`s the URL into `/tmp/ca.pem` and, if it parses as x509, overwrites `/conf/ca.pem`, the lighttpd client-CA. This is an Intel RSD/PODM convention. Security note: a rogue DHCP server can replace the client-cert trust anchor.
- The only "off" options are disabling the whole web service (`[web] current_state=0`, which also kills `/api`) or blocking with the firewall, which works only by IP/port; `/redfish` shares 443 with `/api`. The proxy itself could also refuse to forward `/redfish`.

### 6.3 Web session and CSRF handling

Login is `POST /api/session` (or `/api/asrr/session` for certificate login) with a **form-encoded** body `username`, `password` and `certlogin` (`0` or `1`). From `www/source.min.js`:

```js
e.ajax({type:"POST",url:n?"/api/asrr/session":"/api/session",dataType:"json",
        data:{username:..., password:..., certlogin:n?"1":"0"}, ...
// success: n.ok===0, n.CSRFToken, n.racsession_id, n.privilege, n.extended_privilege, n.server_addr
e.ajaxSetup({headers:{"X-CSRFTOKEN":n.CSRFToken}})
```

- Cookie: `QSESSIONID` (`strings spx_restservice`: `QSESSIONID`, `racsession_id`). The UI clears it with `document.cookie="QSESSIONID=1;expires=Thu, 01 Jan 1970..."`. Session tokens are stored in `/var/session_token` (libtoken) and the session registry in `/var/racsessioninfo` (libracsessioninfo, with `/var/tmp/active_session_cnt` and `/var/session_terminate`). Active web tokens are in `/var/ActiveWebTokens`.
- CSRF: every authenticated request must send the header `X-CSRFTOKEN: <CSRFToken>`; the server reads it as `HTTP_X_CSRFTOKEN`. A missing or invalid token gets `Status: 401 Unauthorized`. The token is the session-scoped `CSRFToken` returned at login. The UI keeps it in `localStorage`/`sessionStorage` under the key `garc`. Binary downloads (for example `/api/logs/video-data/?file=`) also set `X-CSRFTOKEN`.
- Logout: `DELETE /api/session`.
- The viewer has a separate login (`/api/viewerlogin`, `ViewerCsrftoken`, `ViewerUsername`) and a KVM token (`/api/kvm/token`).
- Limits: `ncml.conf [web] max_sessions=148 active_sessions=128 session_timeout=1800 MaxSessionInactivityTimeout=1800 MinSessionInactivityTimeout=300`. Strings: "Could not create token for this session. Max session limit might have reached", "Maximum number of sessions already in use", "WEB Session, MaxAllowSession value::%d" (adviserd). Active sessions are listed and terminated through `/api/settings/service-sessions[/(id)]` (`CONFIG_SPX_FEATURE_SESSION_MANAGEMENT_SUPPORT`).
- ASRock "Web enable timeout": `GET/POST /api/asrr/{get,set}WebEnableTimeout` (`{"enable_timeout":0|1}`), persisted in `/conf/WebDisableTimeout`. It toggles whether the web idle timeout applies.
- `/conf/mutual_login_user` stores the user for mutual-TLS login.
- Lockout: no lockout parameter for the web/IPMI path was found in text config (IPMI 2.0 user lockout is in the LAN parameters in NVRAM). Redfish: 5 failures, then 30 lockout (section 4.6).

## 8. Notes for building the Go proxy

1. **Choose the backend per feature.** Redfish (`/redfish/v1`, X-Auth-Token sessions or Basic auth) is available and is the better general API. Its strings include `X-Auth-Token`, `Basic realm="AMI_Redfish_Server"`, `SESSION_AUTH`, `BASIC_AUTH`, `SessionLimitExceeded`, `NoValidSession` and `AuthenticationDisabled`. Keep `/api` for ASRock-only features: fan tables (`/api/asrr/settings/*fan*`), BIOS flash and import/export (`/api/asrr/maintenance/BIOS/*`), CPLD, MCA logs, PROCHOT, NCSI veto bit and Web-enable timeout. Keep IPMI for power control and SOL as a fallback.
2. **Serialization.** `/api` runs as a single FastCGI process (`max-procs 1`), and each call usually turns into one or more IPMI transactions. Queue requests per BMC; aim for at most 1 or 2 in flight to `/api`. Redfish is a single LuaJIT/Turbo event loop with Redis behind it, so keep concurrency low there as well. Redis is capped at 20 MiB with `noeviction`, so writes fail when it is full.
3. **Session budget.** Web sessions are capped at 128 active (with a hard ceiling of 148), and IPMI at 36 total sessions. The idle timeout is 1800 s for web (minimum 300) and 60 s for IPMI. Reuse one session per BMC and refresh it before it times out. On failures, explicitly `DELETE /api/session`, `DELETE` the Redfish session, or close the IPMI session, so slots are not leaked.
4. **CSRF.** Send `X-CSRFTOKEN` on every `/api` request after login, together with the `QSESSIONID` cookie. The login body is `application/x-www-form-urlencoded`, not JSON. Many settings endpoints take JSON bodies (`contentType:"application/json"` in the UI).
5. **TLS.** Expect a self-signed certificate (the AMI default `CN=www.ami.com`, whose key is publicly known) and TLS 1.2 at most. Leave P-384 enabled. The server sends a CertificateRequest; Go handles that fine with no client certificate. Pin each BMC's cert only after it has been regenerated. Never use port 80: `/asrr/` URLs are deliberately left un-redirected on HTTP.
6. **Response quirks.** Static files always come with `Content-Encoding: gzip`. lighttpd sends `Status:` headers from FastCGI. `/api` responses carry `Cache-Control: no-store`. `server.max-read-idle` and `server.max-keep-alive-idle` are 120 s, so idle keep-alive connections should be recycled before 120 s.
7. **KVM.** H5Viewer uses WebSocket `/kvm` (to 7578) and `/cd-server` (to 5120) on 443 with subprotocol `binary`/`base64`. `websocket.timeout = 0` disables the idle timeout. A proxy needs WebSocket passthrough plus the `QSESSIONID` cookie and the `/api/kvm/token` flow. The legacy Java client needs raw TCP 7578/7582 and 5120–5127.
8. **Restarts.** lighttpd restarts on every interface-up event and after many settings changes (`lighttpd_delayed_restart.sh 2`, `settings/service/web-restart`). Expect brief 502 or connection-refused windows and retry with backoff. During firmware flashing (runlevel 7/8) lighttpd stays up in rc8, IPMI keeps running in rc7, and Redfish stops in rc8.
9. **No firewall or rate limiting by default.** `iptables.conf` is absent, and `mod_evasive` is not loaded even though `evasive.max-conns-per-ip=30` is set. The proxy should enforce its own per-client limits and ideally be the only thing that can reach the BMC network.
10. **Security items to report.**
    - The default TLS private key is shared by every unit running this firmware.
    - Hidden `sysadmin` (uid 0) and `anonymous` shadow entries have password hashes.
    - DHCP option 248 can replace `/conf/ca.pem`.
    - Plain-HTTP access to `/asrr/` is allowed.
    - `CONFIG_SPX_FEATURE_HOST_INTERFACE_NO_AUTH` means the host OS or BIOS can reach Redfish over USB-LAN without credentials.
    - stunnel's default cert expired on 2026-05-30.
