# ASRock Rack X570D4U BMC firmware 2.11.00: stack analysis

Image: `bmc-firmware/X570D4U_2.11.00.ima` (static analysis). Dump:
`firmware-dumped/X570D4U_2.11.00/` (gitignored). The live board runs **1.20.00**,
not 2.11.00. Section 9 lists what the live probe confirmed or refuted
(`docs/x570/live-probe.md`).

Paths below are relative to `firmware-dumped/X570D4U_2.11.00/rootfs/` unless noted.
`RF` means `usr/local/redfish/`.

## 0. TL;DR for the proxy

- **The stack is the same generation as the B650, with the /api dialect of the X470.** It
  runs AMI MegaRAC SPX 13 (`MDS_VERSION 13.0.1`, `FW_CODEBASEVERSION=5.X`) on an AST2500,
  with Redfish `ServiceRoot.v1_5_2`.
  - Like the B650: Redfish takes the `/api` user, because `UNIFIED_USER_ACCOUNT` and the
    `ipmiredfishusersync` agent are present. TLS is modern. There is no `certlogin`. Sensors
    use `settable_flag` with `"NA"` thresholds. The date-time field is `ntp_auto_date`. The
    restore policy is `asrr/GetPowerRestore`.
  - Like the X470: fans use `asrr/settings/*`, and keep-NIC-link-up uses
    `asrr/getvetobit`/`setvetobit`. There is no `settings/fan/*` and no
    `settings/ncsilinkup`.
- **Missing, unlike the X470:**
  - `asrr/GetFanDuty`, `asrr/getprochot`/`setprochot`, `asrr/clearmcalog` and
    `asrr/mca-file`;
  - the `bond_ifc` field (the UI comments it out with `//ASRR`).
- **The default deny list still applies:**
  - present: `logs/help-data`, `settings/download_image`,
    `maintenance/hpm/upgradestatus` and `hpm/verifyimagestatus`;
  - absent: `asrr/mca-file`.

  The proxy needs no X570-specific deny rule.
- **Redfish NetworkProtocol PATCH is synchronous here, like the X470.**
  `RF/redfish/manager/network-protocol.lua` (20.7 KB of LuaJIT bytecode) has
  `pending_commands` and `PATCH_TIMEOUT`. It does not have the B650's
  `patch_task_status_code` (B650 7.02: a 2 KB task-queuing stub that answers 202). Expect a
  blocking 200/204, not 202 plus a task. **UNVERIFIED live**, because the probe made no
  writes.
- **`/ext` is routed** (`lighttpd_ext.conf` is included, unlike on the B650). It points at
  `spx_restservice_ext`, a 26 KB sample FastCGI that serves `/sample/{post,put,delete,getmodel,getcollection}`.
  The proxy never reaches it, because raw passthrough is `/api` only.

## 2. `/api` handler inventory

The method matches `docs/api/scripts/handlers.py`:

- run `strings` on `usr/local/bin/spx_restservice` and the `lib(asrr)spx_restservice*.so.N.N.N`
  plugins;
- route strings mark `handler_present["X570-2.11"]` in `docs/api/legacy-api-endpoints.json`;
- script: `docs/api/scripts/x570_handlers.py`.

Result: 445 catalog entries, 240 present on the X570. 29 X570 routes were missing from the
UI-derived catalog and are appended with area "X570 additions".

| Area | X570 2.11 | X470 3.02 | B650 7.02/9.05 |
|---|---|---|---|
| Fan | `asrr/settings/{get,set}fancontrolmode`, open/close table number + table, `{get,set}fandutymanualmode`, `setclearallfansetting`, `getsupportfan(name)`, `gettscftsupportfan`, `getfantempsensorandcorrespondfantable`, `get/setfan100druingbmcupdate` (new) | same family + `GetFanDuty` | `settings/fan/*` |
| Keep NIC link up | `asrr/getvetobit` / `setvetobit` | same | `settings/ncsilinkup` |
| Restore policy | `asrr/GetPowerRestore` / `SetPowerRestore` | none (IPMI) | same as X570 |
| POST code | `logs/postcode`, `asrr/getbioscode` | `asrr/getbioscode` | `logs/postcode` |
| Inventory | `system_inventory/*` and `host_inventory/*` (UI uses host_inventory) | system_inventory | host_inventory |
| MCA | `asrr/getmcalog` only | getmcalog, clearmcalog, mca-file | getmcalog |
| PROCHOT | absent | `asrr/getprochot` / `setprochot` | absent |
| Maintenance components | BIOS (incl. `UpdateOption`), BMC, BP | BIOS, BMC, CPLD | BIOS, CPLD, FPGA, RETIMER |
| Other | `asrr/smbiosdata`, `settings/ncsi/mode`, `settings/network-bond` (no `bond_ifc`) | | |

Notes:

- `libasrrspx_restservice` carries the string `event_log_count`, as the B650 does. The live 1.20
  does not append the trailer. The driver skips it either way.
- `date-time` has `ntp_auto_date` plus `ptp_*` fields in 2.11. The live 1.20 has
  `ntp_auto_date` only.
- The UI posts `setopenlooptablenumber` as `POST {table_numble}` (sic), as on the X470.

## 3. Redfish

- `ServiceRoot.v1_5_2`, RedfishVersion 1.8.0 (live). `$metadata` declares, among others,
  Sensor, CertificateService, ManagerNetworkProtocol v1_4_2 and TaskService.
- The Redfish daemon runs on 127.0.0.1:9080 behind lighttpd `mod_proxy`.
  - `redfish_lighttpd.conf` loads `mod_evasive` with `evasive.max-conns-per-ip = 10` on
    `^/redfish`.
  - SSE is on :9090.
  - `ssl.verifyclient.*` is enabled but not enforced.
- `SessionService.SessionTimeout` is 30 s (live).
- `GlobalLuaTables` is unauthenticated (live 200), as on every AMI board. It is already in
  `amimegarac.DefaultDenyRules`.

## 4. Accounts, PAM and redis (compared with `docs/x470/redfish-auth-analysis.md`)

| Item | X470 3.02 | X570 2.11 | B650 9.05 |
|---|---|---|---|
| `CONFIG_SPX_FEATURE_UNIFIED_USER_ACCOUNT` | absent | **present** (`etc/core_features`) | present |
| IPMI-to-Redfish sync | none | `usr/local/sync-agent/extensions/ipmi/subagents/ipmiredfishusersync.lua`, `init_agent_scripts/init-user.lua` | same |
| `RF/db_init/zzzaccountservice.rcmd` | Administrator id 1, `LastAccountIndex 3`, no `PAMEnabled`/`LocalAccountAuth` | Administrator id 1, `LastAccountIndex 3`, `LocalAccountAuth "LocalFirst"`, `PasswordChangeRequired`, `MinPasswordLength 8`, lockout 5/30 s | as X570 |
| `PAMEnabled` | not seeded (off) | schema `AMIAccountServiceConfigurations.v1_0_0`; live `false` | live `false` |
| Web PAM stack (`/etc/pam.d/HTTP` symlinked to `/conf/pam_wounix`) | pam_ipmi first | pam_nologin, **pam_ipmi** (`success=done`), then LDAP/AD/RADIUS | same |

Verdict:

- Redfish authenticates the `/api` admin through the synced local account.
- On the live board, accounts are 1 `Administrator`, 4 `admin` (Administrator role, synced) and
  5 `fwupd`.
- PAM is not needed, so the `x470_pam` build tag is **not** extended to the X570
  (`vendors/asrock/x470_pam_autoenable.go` acts only on profile key `x470d4u`).

## 5. Dialect markers

Detection relies on these:

- `asrr/model-name` returns `mb_name` "X570D4U", with `sys_name` "N/A".
- `asrr/fw-info` returns `BMC_fw_version`, `BIOS_fw_version` ("L1.57"), `ME_fw_version` and
  `Micro_Code_version`, with `CPLD_version` "N/A".
- The ServiceRoot is `v1_5_2` / 1.8.0 with `Vendor "AMI"` and `Oem.Ami.RtpVersion "1.8.0"`.
  This places the board in the modern family (`familyFromRoot`); X470-family detection
  matches only v1_1/v1_2/v1_3 or RedfishVersion 1.0, 1.4 or 1.5.
- The `/api` login returns `user_id`, `channel` and `passwordStatus`, the same extras as the
  B650. There are no TFA fields.

## 7. NetworkProtocol PATCH

| Board | `network-protocol.lua` | Behaviour |
|---|---|---|
| X470 3.02 | 16.2 KB, `pending_commands`, `PATCH_TIMEOUT` | synchronous |
| **X570 2.11** | 20.7 KB, `pending_commands`, `PATCH_TIMEOUT`, SSDP | **synchronous** (inferred) |
| B650 7.02 | 2.1 KB, `patch_task_status_code` | queues a NetworkProtocolTask and answers 202 |

The generic Redfish driver handles both shapes, a 2xx body or a 202 with a task monitor.
Nothing X570-specific is needed. This is unverified on hardware.

## 8. TLS

`etc/defconfig/lighttpd.conf`:

```
ssl.use-sslv2 = "disable"
ssl.use-sslv3 = "disable"
ssl.dh-file   = "/conf/certs/dhparam.pem"
ssl.cipher-list = "TLSv1.2 !SHA384 !SHA256 !RSA !SHA !aNULL !eNULL !EXPORT !DES !SSLv2 !3DES !RC4 !MD5 !PSK"
```

- Unlike the B650 list, this one has no `!DHE`, so DHE-RSA suites are offered. The live board
  offers TLS 1.2 ECDHE-RSA and DHE-RSA (4096-bit) AEAD suites, plus TLS 1.3. Go's default
  client config works, so the profile is `transport.ProfileModern`.
- The certificate is self-signed: AMI `CN=megarac.com`, RSA-2048, valid Aug 2019 to Aug 2034.
- lighttpd also sets:
  - `evasive.max-conns-per-ip = 30` globally and 10 on `/redfish`;
  - FastCGI `max-procs 1` (one `/api` worker);
  - an HSTS header.
- Web session idle timeout is 1800 s. `max_sessions` is 148 with 128 active.
